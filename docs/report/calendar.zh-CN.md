# 4.2 Calendar — 让日期、筛选和返回都可见

**负责人：LinHao（用户研究）**

## 4.2.1 原界面问题

学生使用 Calendar，是为了找到某天的课程或考试，确认时间、地点，再返回继续查看其他安排。

旧版 Calendar 有四个明显问题：

| 编号 | 问题 |
|---|---|
| O1 | 筛选藏在一个小图标里。用户看不到当前筛选类别，也看不出列表是否已经应用筛选。 |
| O2 | 选择类别和显示结果之间缺少反馈。用户必须记住自己选过什么。 |
| O3 | Exam 空结果只显示 “No event”。页面不说明哪天没有考试，也不给恢复入口。 |
| O4 | 筛选图标和操作区域太小，手机上很难快速点中。 |

## 4.2.2 对应的 HCI 原则

**系统状态可见。**  
用户应该直接看到当前筛选、结果数量和生效状态，而不是靠记忆判断。

**识别优于回忆。**  
类别和选中状态必须放在界面上，让用户直接认出来。

**错误可以恢复。**  
空结果要说明原因，并给出返回全部事件或修改条件的入口。

**触控目标要够大。**  
Fitts’ Law 说明，更大的目标更容易点中。筛选按钮和课程卡都应支持快速操作。

## 4.2.3 改版设计

新版保留“月份网格 + 当日事件”，把筛选、状态和返回全部放到明面上。

**C01 · 全部事件**  
月份和选中日期保持原位。Filter 按钮加大，日期下方直接显示 `All events` 和结果数量。整张课程卡都能点击进入详情。

**C02 · Class 筛选**  
所有类别和选中状态直接列出。Apply、Reset、Close 分开，用户清楚知道如何应用、清空或退出筛选。

**C03 · 仅课程结果**  
页面显示 `Class ✓`、`1 event on this date` 和 Clear。当前结果为什么只剩课程，一眼就能看懂。

**C04 · 课程详情**  
课程类型、时间、地点、教师和来源分组展示。顶部 `‹ Classes` 和底部 `Back to classes` 都返回 C03，保留刚才的筛选状态。

**C05 · Exam 筛选**  
Exam 沿用 Class 的结构和操作方式，减少学习成本。

**C06 · Exam 空状态**  
页面直接显示 `No exams on this date`，并提供 `Show all events`。用户可以返回全部事件，也可以重新筛选。

## 4.2.4 原型路径

共享首页 H00 的 Calendar 入口进入 C01，C01 是独立 Flow 起点 `Calendar · All`。

主流程：

`H00 → C01 → C02 → C03 → C04 → C03`

其他路径：

- C01 课程卡直接进入 C04。
- C02 切换 Exam 进入 C05，C05 可切回 C02。
- C03 的 Clear 返回 C01，Filter 返回 C02。
- C06 的 Show all events 和 Clear 均返回 C01。
- C01、C03、C06 的 Home 均返回共享首页 H00。

新版把找课程、看详情、切换筛选、处理空结果和返回首页串成了一条完整流程。
