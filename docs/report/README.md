## 每个功能小节统一结构

1. User task and observed problem：谁在什么情境下使用，原界面困难及真实截图来源。
2. Redesign and rationale：改前/改后、具名 HCI 原则、为什么预期能帮助任务；假设与事实分开。
3. Prototype：Figma 入口、主路径、返回、加载/空状态等边界。
4. Evaluation and iteration：真实任务、结果、原话、具体修改及版本。
5. Figure and demo assets：图注、参考文献和约一分钟实际 Figma 演示内容。

## 整合与提交检查

A 从协作主稿导出提交版，统一标题、图号、术语和页数；实质改写由原作者确认。B 检查正文引用与参考文献一一对应，C/D/E 分别复核流程、截图版本和评估数据。

D 以截图为主整合 PPT；视频包含开场、五功能实际 Figma 演示、测试与结论，总时长不超过十分钟。录制后如修改原型，必须同步检查报告、PPT 和视频。最终报告 Word/PDF 与 PPT 打一个 ZIP，视频另交 Canvas；A 保存回执，B 独立复核文件、链接、Figma 查看/评论权限和提交结果。
