# PolyULife 界面分析

使用已安装的 iPhone App on Mac，通过 `mcp__cua_repl` 操作真实 PolyULife 窗口。通常无需 Xcode、Simulator 或 Appium。

首次安装、换机器、Computer Use 未启用，或出现截图/输入权限问题时，先读 [安装与配置](references/setup.md)。已配置好的机器直接进入下方打开流程。

## 打开应用

遵循当前 Computer Use 工具文档。新会话第一次调用仅选择一个入口，读取返回的文档和状态后继续。例如：

```javascript
var polyuLifeApp = await cua.getApp("/Applications/polyuLife.app");
```

应用显示名称通常为 `polyuLife`，bundle ID 为 `polyu.its.mobi.psma.prod`；上述路径是本机已观察到的安装位置，其他机器以实际安装位置为准。

- **成功条件**：得到属于 PolyULife 的实际窗口状态；需要视觉判断时再取 `getScreenshot()`。仅收到启动请求或找到安装文件，还不能宣称可观察。
- 遇到 `Running application not found`、bundle ID 歧义、连接后没有窗口，读 [连接与恢复](references/connection.md)。iOS App 的实际运行路径可能位于临时 `Wrapper` 容器，需从本次发现结果中选择。
- 保留用户当前页面和登录状态；用户指定流程时，从该流程合理的起点开始，不擅自清空数据或退出登录。

## 观察与操作

1. **确定目标**：使用用户指定的页面或任务。范围较宽时先选一条短流程；Room Enquiry 可作为候选，实际入口以当前界面为准。
2. **确认当前状态**：结合截图与 `getAXState()` 读取页面标题、可见入口、选中项、加载/错误/空状态。控件树可能包含重复父容器、未显示的菜单文字和私用区图标字符，不能仅靠其文本断言某元素可见。
3. **执行一步并核对结果**：优先使用最新状态中的元素索引；图标无法辨识或索引点击不适用时，用新截图定位坐标。动作后调用 `getAXState()`，必要时截图，确认界面反馈后再决定下一步。不要跨页面复用旧索引或坐标。
4. **保留可复查证据**：按任务需要记录关键状态和动作，说明版本、运行环境、起点及结果。截图以可见内容为证，AX 信息用于补充文字与控件结构。

普通导航、查询、筛选、滚动和返回可在已授权分析范围内执行。分析请求本身不授权提交预约、取消记录或修改资料等业务操作；在对应提交动作前核对用户授权。系统或登录要求用户参与时，报告当前具体提示。

若点击没有反馈，先检查新状态，区分加载、目标不匹配、遮挡与业务错误；按证据做一次针对性修正。仍无进展时记录卡点，改走另一条已授权的观察路径或请求缺失的用户动作，不反复盲点。

## 形成 HCI 分析

把事实、解释和验证分开；发现多少写多少，不凑问题数量。可用下列记录形式：

| 用户目标与页面 | 观察事实与证据 | 问题假设及原因 | HCI 原则与改进建议 | 待验证事项 |
| --- | --- | --- | --- | --- |
| 指定流程中的一步 | 截图编号/路径、动作、实际反馈 | 为什么可能影响该目标；注明不确定性 | 具名原则及其与问题的因果关系 | 需要补看哪种状态或向真人验证什么 |

- 只评价实际看过的状态；未进入的页面、未完成的流程和推测均明确标注。
- 图标 AX 标签缺失可能影响工具或辅助技术；其是否影响一般用户，需要结合视觉界面和用户证据判断。
- 区分 App 行为、网络/数据状态、Mac 适配差异和 Computer Use 定位问题，避免把工具失败归为 App 缺陷。
- Mac 上的观察可支持导航、文案、信息层级和状态反馈分析。单手可达性、触控误触、手势手感及设备功能需回到真实手机验证。
- Agent 的成功路径、等待时间和疑惑不是人类测试指标。用于 COMP3423 时，真实参与者与 Maze 等课程要求以当前项目说明为准，不能用 Agent 模拟替代。

## 输出与完成标准

根据请求交付简短结论或带截图索引的分析记录。明确：观察了哪些页面、实际执行了哪些动作、哪些结果得到确认、哪些尚未验证；一次首页读取只证明该页面可观察。

证据存入用户指定位置或当前项目约定的输出目录，附可点击路径。共享版截图与记录去除无关姓名、学号、账户及二维码；skill 本身只保存操作知识，不保存个人页面内容。若需要写入 School Wiki，遵循其当前入库约定，普通界面分析不自动修改课程待办或团队文档。
